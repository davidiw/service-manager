## Agent handback

The coordinator retains design choices, invariants, scope changes and finding adjudication. Delegate
settled code edits, repository search, focused tests and long-running commands to the cheapest capable
context (`explorer` for search, `operator` for mechanical commands, `worker` for bounded implementation).
Give each assignment an owner, invariant, allowed scope (files/seams), required regressions, non-goals,
an explicit budget (wall-clock, maximum threads or commands) and a handback condition. Reuse complete
worker evidence rather than repeating its campaign.

On timeout, infrastructure failure or loss of useful progress, the worker returns: exact snapshot and
assigned scope; commands completed and outcomes; artifacts produced; confirmed findings; unresolved
questions and the next smallest action. A timeout does not authorize restarting the same exploration; continue
from the handback, narrow it, or close it as blocked. Agents do not expand scope during handback.

When several workers change cooperating owners (for example the release gate and an executor), the
coordinator makes one short composition pass before independent review: which sequences cross changed
owners, and what happens at each transition. Record one to three such scenarios in the review packet as
neutral questions.

## Fragility checkpoint

Pause production edits for a behavior when remediation starts requiring a second persisted
representation, another mutation or orchestration path, hidden coordination state, cross-layer special
cases, or repeated review loops around the same invariant; treat increasingly artificial fixtures as the
same signal. Present the owner with the violated invariant, the confirmed execution path, why the design
resists correction, the smallest simplifying options and a recommendation. Resume after the owner chooses.

## Independent adversarial review

Required for changes to authentication, authorization, the release/disclosure gate, credential handling,
executors or mutation recovery, persistence/migration, and comparable high-risk cross-layer work named
before review. Ordinary changes use focused checks only.

- Use a fresh `reviewer` context without builder history, given a neutral packet: scope, changed behavior,
  non-goals, changed files, test results, known failures and reviewer questions. Builder self-review never
  satisfies the gate.
- Budget: ten elapsed minutes or three targeted investigation threads, whichever comes first. One thread is
  one concrete failure hypothesis, its execution path and its direct validation.
- Classify a finding as `BLOCK` only with a plausible execution path in the change and evidence it violates
  a specific invariant with material consequence (disclosure leak, unauthorized mutation, data loss,
  incorrect operation outcome). Speculative fragility is a non-blocking follow-up. Report at most five
  findings, ordered by severity and confidence.
- The reviewer returns findings without implementing corrections. Batch corrections, reuse the same reviewer
  for a delta review, then run the final verification path once on the corrected tree.

## Commit boundaries

One commit per coherent behavior or tightly coupled slice, with its tests. Include only files belonging to
the slice. Commit after the slice and its focused checks pass rather than accumulating one opaque change.
Before finishing multi-request work, compare the commits with the requested outcomes.
